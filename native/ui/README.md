# Desktop UI: карта для разработчика

Для пользователя: [редактор эксперимента](../../docs/experiment-editor.md) и
[справочник всех параметров](../../docs/editor-parameters.md).
Редактор живёт в отдельном GLFW/ImGui-контексте (`EditorDesktop`), а не в окне viewer.
`DesktopHost` маршрутизирует события ввода по окнам и восстанавливает основной
контекст после кадра редактора. Preview-ресурсы уничтожаются в создававшем их
контексте. Связь окон — документ и команды, не общие ImGui-состояния.

Ориентир для C#: `application` — запуск и application service,
`viewer`/`editor` — представления и их состояние, `platform` — инфраструктура.
Не MVVM: нет binding engine, контейнера DI, иерархии ViewModel или виртуального
вызова на каждом физическом шаге.

```text
native/ui/
├── include/battery_ui/       публичные API модуля и документа
└── src/
    ├── application/
    │   ├── application.cpp  сборка приложения и главный цикл
    │   ├── viewer_session.cpp  запуск/пауза/reset, шаги, replay, снимки
    │   └── options.cpp      CLI-параметры
    ├── platform/
    │   └── desktop_host.*   GLFW, ImGui/OpenGL lifecycle, кадр, screenshot
    ├── viewer/
    │   ├── viewer_window.*  состояние отображения, hotkeys, сборка панелей
    │   ├── scene_view.cpp   3D viewport, камера, выбор объекта
    │   ├── panels/          заголовок, инспектор, управление проигрыванием
    │   └── widgets.*        общая легенда/цвета/флаги окон viewer
    ├── editor/
    │   ├── experiment_editor.cpp  публичный фасад редактора
    │   ├── editor_internal.hpp   приватное состояние форм и объявления
    │   ├── state/          документ, undo/redo, неприменённые правки модели
    │   ├── commands/       импорт, удаление элементов, сборка электрической цепи
    │   ├── views/          окно редактора, вкладки, файловый диалог
    │   ├── panels/         assembly, heating, models, shell, case, circuit, run
    │   ├── forms/          повторно используемые формы материалов/нагревателей
    │   └── preview/        пересборка и отрисовка предпросмотра
    └── shared/             поля форм, toolbar, взаимодействие с viewport
```

## Кто чем владеет

- `ViewerSession` владеет **либо** живой `Simulation`, **либо** записью
  `VisualReplay`. Предоставляет команды и read-only состояние. Здесь нет окна,
  ImGui или OpenGL. `battery_viewer_session` тестируется без графического контекста;
  для живого расчёта по-прежнему нужна CUDA.
- `ViewerWindow` владеет камерой, настройками отображения и renderer. Панели
  читают снимок сессии и отправляют команды, но не вызывают `Simulation::step`.
- `ExperimentEditor` владеет редактируемым `EditorDocument`. Приватный `Impl`
  хранит также черновые поля форм, выбор и кэш preview. Это UI-состояние,
  не физическое состояние работающей симуляции.
- `DesktopHost` управляет ресурсами окна по RAII — аналог `IDisposable`/`using`.
  Он живёт дольше renderer и редактора: GL-ресурсы освобождаются до контекста.
- Физика остаётся в `native/core`; проверка и компиляция контракта —
  `native/run`; построение визуальных данных и renderer — `native/visualization`.

## Путь изменения

```text
поле редактора → EditorDocument → validate/compile → pending snapshot
   → application → ViewerSession.start_snapshot → новая Simulation
   → committed VisualFrame → ViewerWindow / renderer
```

Редактирование не мутирует запущенный расчёт. `RUN SNAPSHOT` создаёт отдельного
кандидата; ошибка загрузки/создания не уничтожает предыдущую сессию. Preview
имеет собственную симуляцию только для исходного снимка, не шагает по времени.
JSON остаётся форматом контракта, но не протоколом связи панели с солвером.

Сессия обрабатывает паузу, события и reset в одном месте. Главный цикл выделяет
пакету физических шагов прежний бюджет 8 мс; это **не** физический `dt`. Шаг,
CUDA-ядра, связи, балансы и коэффициенты от рефакторинга не меняются. Кадр
обновляется после принятого состояния, а не отдельно из каждой панели.
Ссылки на снимки и GPU-поля нельзя сохранять через следующий шаг/reset.

## Где менять функциональность

| Задача | Место |
| --- | --- |
| Поле модели или нагревателя | `editor/forms/`, соответствующая `editor/panels/` |
| Новая вкладка | `editor/views/editor_window.cpp` и отдельный файл в `panels/` |
| Импорт/удаление/изменение документа | `editor/commands/`, `EditorDocument`; контрактные операции в `native/run` |
| Действие над расчётом | метод `ViewerSession`, затем кнопка в панели |
| Газ, огонь, повреждения, цилиндры | `native/visualization`, не панели редактора |
| Окно, шрифт, тема, screenshot | `platform/desktop_host.cpp` |
| Физический закон или интегратор | `native/core`, не `ViewerSession` |

Новые UI `.cpp` регистрируются в `cmake/visualization.cmake`. Заголовки внутри
UI подключаются относительно `src`, например `editor/state/model_edits.hpp`.
Не возвращайте все файлы в одну папку и не переносите вычисления в `draw_*`.

## Проверки и независимая сборка

`tests/test_native_architecture.py` проверяет направление зависимостей и отсутствие
шага физики в панелях. `cuda_viewer_session` сравнивает последовательность живых
шагов с прямой `Simulation`, проверяет reset, неуспешный/успешный snapshot,
replay и автоматические паузы. UI-тесты находятся в `native/tests/visualization`.

Build preset `viewer` собирает desktop. Configure presets `server`/`core` не
подключают этот модуль и графические библиотеки. Будущий сервис строится поверх
`native/job`/`native/run`, а не вокруг окна. Сетевого UI-клиента этот рефакторинг
не добавляет.
